1. Ce qui fonctionne dans cette version

  • Installation avec jeton privé et création d’un compte administrateur.
  • Connexion, limitation des tentatives, protection CSRF, mot de passe haché et expiration après deux heures d’inactivité.
  • Clients : création, modification, recherche, pagination, archivage et réactivation.
  • Commandes : client, service, spécifications, quantité, unité, prix, total, statut, priorité, livraison.
  • Calcul des montants en centimes, tableaux de bord calculés à partir de la base, exports CSV et journal d’activité.
  • Nom de l’entreprise, fuseau horaire et changement du mot de passe.

Les avoirs sur factures, devis avant commande, leur acceptation et conversion, documents multilignes, règlements et chèques simples sont disponibles. Les employés, permissions, tâches, présences et évaluations manuelles sont disponibles. Charges et caisse/banque sont disponibles. Suivi complet des chèques, rapprochement, réclamations, objectifs commerciaux et analyses financières avancées restent prévus dans les étapes suivantes. Il n’y a pas encore d’import CSV, de restauration intégrée ou de récupération du mot de passe par e-mail.

Le CA client est net des avoirs HT ; les dettes et soldes en faveur du client sont affichés séparément. Aucun remboursement automatique. La « valeur des commandes » est une valeur interne saisie, hors TVA, avec taux configurable sur chaque commande pour calculer le TTC. Elle est distincte du CA facturé affiché dans les clients et des encaissements. Une commande contient désormais de 1 à 50 lignes : désignation, quantité, unité, prix HT, remise et TVA. Voir le guide V0.5 pour les règles d’arrondi.

2. Préparer votre cPanel

  1. Activez PHP 8.2 ou supérieur en 64 bits, avec PDO, pdo_mysql, mbstring et zlib. PHP doit disposer de sessions et des fonctions standard de hachage.
  2. Utilisez MySQL 8.0+ ou MariaDB 10.6+. Le compte doit pouvoir créer les tables, index et clés étrangères de sa base.
  3. Activez le certificat SSL et ouvrez toujours l’application en HTTPS. Utilisez un hébergement Apache ou LiteSpeed compatible avec les restrictions de dossiers livrées dans l’archive. Un hébergement purement HTML ne peut pas exécuter cette version.
  4. Dans « MySQL Databases » : créez une base, un utilisateur et un mot de passe fort. Associez l’utilisateur à la base avec les droits nécessaires. Les noms cPanel incluent souvent un préfixe de compte.

Exemples de valeurs fictives : base moncompte_cmyk, utilisateur moncompte_cmykuser, hôte localhost. Utilisez les valeurs réelles affichées par votre hébergeur. Ne partagez pas vos mots de passe dans la conversation.

3. Envoyer et installer

  1. Envoyez CMYK_Designs.zip dans public_html puis choisissez « Extract ». L’archive crée le dossier cmyk-designs. Vous pouvez le renommer en gestion avant l’installation si vous préférez.
  2. Dans le dossier app, copiez config.example.php vers config.php. Éditez seulement les valeurs entre apostrophes : hôte, port, nom de base, utilisateur, mot de passe MySQL.
  3. Dans setup_token, remplacez le texte commençant par CHANGE_ME par une chaîne aléatoire d’au moins 32 caractères. Utilisez votre gestionnaire de mots de passe pour la générer ; évitez les apostrophes et antislashs pour simplifier l’édition PHP. Le jeton n’est pas le mot de passe administrateur.
  4. Ouvrez https://votre-domaine/cmyk-designs/install.php en remplaçant le domaine et, si nécessaire, le nom du dossier.
  5. Entrez ce jeton, votre nom, votre e-mail et un mot de passe administrateur d’au moins 12 caractères (72 octets maximum). Aucun identifiant par défaut n’est fourni.
  6. Après le succès, supprimez install.php dans cPanel, puis ouvrez l’application. Le verrou en base empêche également une seconde installation.
  7. Créez un client, créez une commande, modifiez sa situation et vérifiez l’export. La base initiale est vide : aucune entreprise ni donnée de démonstration n’est injectée.
باش ترفع النسخة الجديدة من بعد: دير sauvegarde، بدّل غير ملفات البرنامج، وخلي app/config.php وقاعدة البيانات. ما تعاودش installation فوق بياناتك.

4. Sauvegarder les données

  • Avant chaque mise à jour, exportez la base entière via cPanel / phpMyAdmin, en SQL avec structure et données. Conservez aussi une copie de app/config.php et de la version de code actuelle.
  • Les exports CSV de l’application contiennent les clients ou commandes et servent à l’analyse. Ils ne constituent pas une sauvegarde complète restaurable : ils ne contiennent pas comptes, configuration ni journal complet.
  • Pour restaurer : utilisez une nouvelle base vide de test, importez le SQL sauvegardé, pointez une copie du code de la même version vers cette base, puis vérifiez la connexion et les enregistrements avant tout remplacement en production.
  • Rangez les sauvegardes hors du dossier public du site et limitez leur accès. Activez les sauvegardes cPanel si votre offre le permet.

5. Procédure de mise à jour à chaque étape

  1. Vérifiez le numéro dans VERSION.txt et lisez CHANGELOG.md et la note de migration livrée avec la prochaine version.
  2. Effectuez et vérifiez les sauvegardes complètes ; testez d’abord la nouvelle version sur une copie séparée, avec sa propre base.
  3. Remplacez les fichiers de code du dossier existant avec le contenu de l’archive mise à jour. Ne supprimez ni app/config.php ni la base MySQL. L’archive ne contient pas votre configuration réelle.
  4. Si le schéma doit évoluer, appliquez uniquement la migration explicitement prévue pour votre version. Ne relancez pas install.php pour mettre à jour. Utilisez upgrade.php, connecté comme administrateur, pour passer des schémas 1 à 10 au schéma 11. Consultez MISE_A_JOUR_V08.html.
  5. Vérifiez le nombre de clients, les commandes, les montants, l’authentification et les exports. Reprenez l’activité après ces contrôles.
  6. En cas de retour arrière : restaurez ensemble le code et la base issus de la même sauvegarde. Évitez de restaurer seulement la base après de nouvelles saisies.

La version téléchargée reste le même projet. Une version livrée ensuite doit remplacer les fichiers de ce projet, et non créer une seconde application.

7. Dépannage

  • Erreur de base : vérifiez le nom avec préfixe cPanel, l’utilisateur, son association à la base, le mot de passe et l’hôte. Consultez le journal PHP de cPanel ; l’application n’affiche pas les détails SQL aux visiteurs.
  • Retour incessant à la connexion : utilisez toujours le même domaine HTTPS, autorisez les cookies et vérifiez que les sessions PHP fonctionnent chez l’hébergeur.
  • Erreur HTTP 500 dès l’ouverture : consultez le journal cPanel pour une extension PHP absente, une erreur d’édition de configuration ou une directive Apache non autorisée. Faites corriger la cause par l’hébergeur plutôt que de retirer la protection des dossiers.
  • Trop de tentatives : attendez 15 minutes après les tentatives ayant déclenché le blocage. Le compteur est lié à l’adresse réseau et à l’identité essayée.
  • Mot de passe oublié : cette version ne dispose pas de réinitialisation par e-mail. La récupération nécessite une intervention administrateur dans la base avec un hachage PHP valide ; ne réinstallez pas l’application.
